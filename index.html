产品能力

日程在手，数据不离开你的 Mac

本地同步服务通过 lark-cli 获取工作摘要，经 Bluetooth LE 分片传输并校验，卡片只保存用于展示的最近摘要。

工作摘要

聚合今日日程、近 30 天待办、未读消息计数与账号信息。

本地 BLE 同步

自动发现设备，分片传输、CRC 校验，并由卡片完成最终确认。

凭证隔离

飞书凭证、macOS 蓝牙权限、配对记录与同步日志只保留在 Mac。

离线可读

有效摘要写入卡片 NVS，断连或重启后仍可查看最近一次内容。

用户使用指南

快速开始

首次使用只需 4 步：刷入固件、准备设备、启动同步服务，然后在 Mac 上完成蓝牙配对并等待摘要写入。

  1. 1

    刷入固件

    刷入包含 Work Assistant 的固件，并保持充足电量。

    打开网页刷机工具
  2. 2

    准备设备

    给 AI Passport 充电并开机，放在 Mac 蓝牙连接范围内。

  3. 3

    启动同步服务

    解压 macOS 脚本包，在 Terminal 运行 bash start.sh。

  4. 4

    配对并同步

    在 macOS 弹窗输入卡片上的六位代码，等待最新摘要出现。

使用时请保持：同步服务的 Terminal 窗口不关闭、Mac 蓝牙已开启、卡片在连接范围内。首次配对不要在 macOS 系统设置中手动连接同名 BLE 设备。

03

第 1 步

启动 Mac 同步服务

  1. 1

    下载 AI-Passport-Sync-macos.zip 并解压。

  2. 2

    打开 Terminal，输入 cd ，把解压后的 AI Passport Sync 文件夹拖入窗口，按 Return。

  3. 3

    启动服务，并保持 Terminal 窗口打开。脚本会自动检查环境和安装缺失依赖。

    bash start.sh
  4. 4

    浏览器会打开本地同步台。若未自动打开，使用 Terminal 显示的地址，默认是 127.0.0.1:4177。

  5. 5

    等待自动同步，或在页面点击“立即同步”。

压缩包不包含 Node modules、Python 虚拟环境、飞书凭证、BLE 配对记录或同步日志。每位用户首次启动时会在自己的 Mac 上完成依赖安装和授权。

04

第 2 步

首次配对与日常同步

首次同步

  1. 卡片没有历史数据时会立即广播，等待 Mac 发现。
  2. 同步服务发起连接后，在 macOS 弹窗输入卡片显示的六位配对码。
  3. 等待网页显示设备确认，卡片会切换为最新工作摘要。

后续同步

  1. 进入解压后的目录，执行 bash start.sh，并让卡片保持在附近。
  2. 服务启动后会自动同步，也可手动点击“立即同步”。
  3. 断连不会清除卡片数据。重新配对时，卡片会自动展示新的配对码。
05

第 3 步

查看状态并处理异常

卡片或网页提示 处理方法
Waiting for computer.

卡片正在广播。确认 Mac 蓝牙开启，并让同步服务继续运行。

Enter the pairing code on your computer.

在 macOS 的蓝牙配对弹窗中输入卡片显示的六位代码。

Receiving work data.

正在传输和校验。保持卡片在附近，不要关闭 Terminal。

Bluetooth sync failed.

检查蓝牙权限、卡片电量和 lark-cli auth status --verify，然后点击“立即同步”重试。

网页无法打开

确认 Terminal 未关闭；如果默认端口冲突，以 Terminal 输出的地址为准。

停止服务时，在应用打开的 Terminal 窗口按 Control + C，然后关闭窗口。

开发者二次开发指南

架构与职责边界

组件 职责 不应承担的职责
main/ 界面、状态机、BLE bridge、持久化摘要与应用逻辑。 复用的板级引脚与外设细节。
components/bsp/ 显示、按键、音频、电量计、I2C 等板级能力；硬件参数以 bsp_pins.h 为唯一事实来源。 业务页面或飞书同步逻辑。
tools/passport_bridge/ 通过本机 lark-cli 汇总数据，并经 CoreBluetooth/Bleak 传输摘要。 保存或暴露飞书凭证。
tools/passport_web/ 仅监听 localhost 的同步控制台和进度展示。 替代本机蓝牙服务，或部署为云端 BLE 服务。

固件兼容性契约：目标固定为 ESP32-C3、8 MB Flash、无 PSRAM、ESP-IDF 5.5.3。不得移动或覆盖 cardid（0x356000）和永久 Recovery（0x700000）；不得执行 idf.py erase-flash。已有身份的设备优先使用小程序 BLE 安装或安全的分段更新。

08

工程约束

扩展规范与交付检查

  • 新增硬件参数先更新 components/bsp/include/bsp_pins.h，不要在应用 C 文件重复定义 GPIO、I2C 地址或屏幕尺寸。
  • LVGL 不是线程安全的；LVGL 任务外访问对象必须持有 bsp_lvgl_lock()。
  • 按键回调不能阻塞。网络、存储、音频与 BLE 等耗时操作使用工作任务。
  • 协议、状态机、时间和布局计算应与 ESP-IDF/LVGL 解耦，并添加 host tests。
  • BLE 摘要协议必须保持长度、序列、CRC 和最大负载限制兼容；修改时同步更新固件、Python bridge 和测试。
  • 不要将飞书 token、app secret、设备 QR 密钥、蓝牙标识或用户日志提交到仓库或放入 macOS 分发包。
